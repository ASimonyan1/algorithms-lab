# Идеи, инварианты и вопросы

1. **Lower bound:** поддерживаем полуинтервал `[lo, hi)`. Всё слева от `lo` меньше цели. При равенстве сдвигаем правую границу: нужны первые дубликаты, не случайный совпавший элемент. Почему `lo + (hi - lo) / 2` безопаснее суммы границ?
2. **Merge sort:** перед слиянием обе половины уже отсортированы. Буфер создаётся один раз, при равенстве берём левый элемент. Как доказать стабильность обобщённой версии?
3. **Two Sum:** в таблице только предыдущие индексы, поэтому один элемент не используется дважды. Дополнение вычисляется в int64_t. Что произойдёт при коллизиях?
4. **Скобки:** стек хранит незакрытые открывающие скобки. Закрывающая обязана соответствовать последней. Остальные символы игнорируются. Почему подсчёта количества скобок недостаточно?
5. **Скользящее окно:** левая граница никогда не уменьшается. Для каждого байта храним индекс после последнего появления. Почему `abba` ломает вариант без `max`?
6. **Kadane:** `ending` — лучший непустой подмассив, который заканчивается здесь. Либо продолжаем его, либо начинаем заново. На полностью отрицательном входе ответ не ноль.
7. **Интервалы:** после сортировки новый интервал либо продолжает последний результат, либо начинает новый. Замкнутые `[1,2]` и `[2,3]` пересекаются; для полуинтервалов контракт был бы другим.
8. **BFS:** вершина помечается при добавлении в очередь. Первое достижение даёт кратчайшее расстояние по числу рёбер. Для взвешенного графа это неверно.
9. **DFS:** явный стек устраняет риск переполнения стека вызовов. Пометка при извлечении сохраняет порядок обхода, но допускает повторные элементы в стеке; поэтому память O(V+E).
10. **Топологическая сортировка:** удаляем вершины без входящих рёбер. Если удалены не все вершины, остался цикл. Порядок не обязательно единственный.
11. **LIS:** `tails[k]` — минимальный возможный последний элемент возрастающей подпоследовательности длины k+1. Это не обязательно сама подпоследовательность. Для неубывающей версии нужен upper_bound.
12. **Монеты:** `best[x]` — минимальное число монет для суммы x. Переход перебирает последний номинал; повторное использование разрешено. На `{1,3,4}`, сумме 6 жадный выбор хуже динамики.
13. **Очередь:** каждый элемент один раз попадает во входной стек, один раз переносится и один раз удаляется. Одна дорогая операция не отменяет амортизированную O(1).
14. **MinStack:** рядом с элементом хранится минимум префикса. Дубликаты минимумов должны переживать удаление одного из них.
15. **HashMap:** цепочки разрешают коллизии; расширение перераспределяет все ключи по новому модулю. Средняя O(1) требует подходящей хеш-функции, гарантии в худшем случае нет.

## Как готовиться

Для каждого алгоритма объясните контракт, пройдите пример вручную, назовите инвариант и сложность, добавьте собственный тест. Затем реализуйте его заново без просмотра исходника. История репозитория показывает создание лаборатории; она не означает, что все темы уже освоены автором.
